## 逐項決策要點

上表硬體欄凡未明確標為官方檔案大小、官方部署配方或明示配置者，均是依參數數量乘精度的**容量推估**：BF16/FP16 約每參數 2 bytes、FP8/INT8 約 1 byte、理想 4-bit 約 0.5 byte。這不是最低顯存承諾；KV cache、量化尺度、runtime buffer、視覺編碼器、批次與並行請求均會提高需求。對長 context 系統，應以同一 runtime 實際量測峰值 VRAM、吞吐及延遲，不以啟用參數數估完整 MoE 權重。

權重授權只管模型檔及其衍生／再散布條件；Transformers、vLLM、SGLang、llama.cpp、Ollama 等 runtime 各有軟體授權；QwenCloud、Gemini、Mistral API、DeepSeek API、Foundry、watsonx 或第三方推論端點則另受服務條款、資料政策、價格與可用性限制。**可下載、自託管或權重採寬鬆授權，均不自動代表託管服務可用、免費、可保留資料，或其 runtime/API 已符合 Reasona 需求。**

- **Qwen Flash-Next：**權重的 MaaS／AI Work Assistant 門檻與 Reasona AI 可能的代理產品形態高度相關，需先取得法律判定／授權；API 費率不能代替授權。中文及繁中無專項證據；模板工具格式可用，但 JSON Schema 保證僅見於託管 API 能力，且多模態情境有限制。長 context 與 125B 主模型令硬體預算遠高於「6B 啟用」直覺。
- **Llama 4 Scout：**Community License 與 AUP 不等於無限制商用；另須評估歐盟多模態限制。工具 parser 可處理結構，但不構成模型必然遵循 schema 的保證。10M 是輸入 context 宣稱，部署記憶體與實際輸出長度仍須另測；繁中未驗。
- **Gemma 4 31B：**Apache-2.0 權重許可相對直接，是可自託管商用的候選；建議首輪以 vLLM recipe 試 tool parser 與 guided JSON Schema。Google Gemini API 免費層的資料使用規則不能套用或移植到本地權重；反之 Apache 權重也不豁免 API 條款。
- **Mistral Medium 3.5：**卡片明列 Chinese，且模型有 function calls/JSON 能力；繁體仍須自行測。Modified MIT 月營收限制需事前由法務核准。官方服務 API 價格和本地權重許可分開；SGLang/vLLM 專用配方不等於所有硬體和穩定版都支援。
- **DeepSeek V4.1 Flash：**有中文 benchmark，但不應把中文評分當繁中產品品質。MIT 權重與 API 資料政策分開；官方 API policy 頁未能核對是正式上線前的阻擋事項。552B 總權重和預覽 runtime 使它不適合以小型單機 MVP 假設部署。
- **Granite 4.2 30B：**Apache-2.0 且列 Chinese，工具呼叫有模型模板與 runtime parser 路徑；繁中與 JSON 約束仍要實測。30B 的 IBM benchmark 是廠商報告，且 30B 並非所有基準都高於 8B。IBM 託管供應及價格未核得，先以自託管或另核服務為前提。
- **Phi-4 Reasoning Vision：**MIT 權重可商用，但這個 checkpoint 的目標是 GUI/computer-use，而非已驗證的一般 function calling。若產品重點是點按 UI 或理解螢幕，可獨立做視覺代理試驗；若是文字 Agent，勿將 Foundry chat endpoint 當成原生工具能力證據。中文證據不足且 context 僅 16K。
- **gpt-oss-20b：**Apache-2.0、較低自託管權重成本、vLLM 專用部署文件使之適合作為本地基線；其訓練以英文為主，Chinese MMMLU 不等於繁中品質。OpenAI API 雖有模型頁，但速率為 0 且未查得專屬價格，MVP 不應依賴未確認的代管供應。
- **OLMo 3.1 32B：**模板有 tool-call 格式，但官方 parser 的具體工具示例是 7B，32B 應自行驗證。Apache-2.0 權重與 Ai2 Responsible Use Guidelines 的適用關係有文字張力，需法律釐清；模型卡列 English，故繁中風險高。
- **Tiny Aya L2-Thinker：**卡片列中文而非繁體專項，且 32K 是 input/output 合計；小尺寸不消除 CC-BY-NC 商用限制。Cohere API 列出的其他 Tiny Aya 型號不能推定此 checkpoint 已託管或有工具/schema 能力。

## MVP 搭配建議

1. **研究主模型：Granite 4.2 30B；用 vLLM 先做可追溯研究流程。**在本批候選中，它同時有 Apache-2.0 權重授權、官方列 Chinese、128K 原生／512K 延展 context，以及 tool-call 模板和 vLLM/SGLang parser 路徑，適合作為商用自託管的首輪主模型候選。把來源擷取、段落切分、引用識別與證據存檔交給產品管線；模型負責在限定來源中抽取 claim、摘要、比較及輸出 schema。取捨是 30B 的 GPU 成本、繁中仍無獨立驗證、IBM 公布基準未獨立重測，且長 context 對 KV cache 的消耗不低；512K 是延展配置而非無成本預設。

2. **長文研究／結構輸出對照：Gemma 4 31B-it + Granite 4.2 30B 受控 A/B。**Gemma 權重 Apache-2.0、標示 35+ 語言直接支援，vLLM 有工具解析與 JSON Schema constrained output；可與 Granite 的中文明示、512K 延展和 Agentic RL 路徑比較。以相同來源包、同一硬體/runtime/量化條件測繁中證據抽取、引文忠實度、schema 合規、延遲與成本，不預先宣稱勝者。Gemma 沒有單列中文/繁中分數，Granite 也沒有繁體專項基準；兩者都須產品自有測試。若無 80GB 級卡，先用可取得硬體的兩模型相同量化配置測小規模樣本，記錄品質和量化代價，不據此承諾生產容量。

3. **若營收許可且需要更強 Agent 研究對照：加入 Mistral Medium 3.5 128B。**其官方卡列 Chinese、native function calls／JSON output、256K context，適合作為能力與工具流程的高資源比較組；但 Modified MIT 的前月全球合併營收門檻、128B GPU 費用、夜間版／專用部署限制均需先處理。這是有條件的評估候選，不是預設主模型。若團隊要低成本單機試驗，可另以 gpt-oss-20b 做小模型摘要／分類基線，但其訓練以英文為主、繁中品質未證實，且 128K context/能力取捨不適合作為完整來源密集研究流程的當然替代。

**目前建議的決策方式是先以 Granite 主模型、Gemma 對照組做研究工作流 MVP，再以自有評測決定是否引入 Mistral 或小模型分層。**Qwen Flash-Next 雖有百萬級 context 和 agent 方向，但 MaaS／AI Work Assistant 授權條件可能與 Reasona 產品形態重疊，且需龐大多卡部署，除非先取得授權並驗證經濟性，否則不列初始商用候選。Cohere Tiny Aya L2-Thinker 的 CC-BY-NC 不適用商用 MVP。DeepSeek V4.1 Flash 長 context 與中文 benchmark 有研究價值，但 552B 權重及前沿部署需求不符合輕量起步。託管服務只能在核對型號可用性、地區、服務條款、資料保留／訓練政策與當前費率後納入；權重許可不涵蓋這些 API 條件。

### 來源引用與可追溯性：模型能力 vs. 產品管線

模型可以協助讀取已擷取的段落、提出摘要與 claim、生成引用候選、標示不確定性或依 schema 輸出；若提供來源內容和 ID，也可生成指向來源的引用。但「引用看起來合理」不代表 claim 真由該來源支持，也不證明 URL 有效、來源當時可讀、版本未變或涵蓋足夠。模型生成引用不得當成來源證據或可追溯性的唯一依據。

來源追溯必須由應用／研究管線負責：抓取並保存 URL、擷取時間、頁面標題、內容雜湊／版本與段落定位；把每個 claim 綁到具體來源片段，保留擷取與轉換紀錄；產生短報告時只接受可回溯的 evidence ID，另做 URL 狀態／重新導向檢查、主張—證據相符驗證、來源新鮮度與覆蓋度檢查。模型可提出引用關係與 evidence span，產品需能拒收無來源 claim、呈現未驗證標記並支持人工覆核。對動態頁面，要保存當時擷取快照或摘要雜湊；不能只依賴日後仍可開啟的 URL。

### 應用層／編排層功能責任

Reasona 的產品層功能需求應明確拆為：**新增／刪除對話、Google 登入、個人 Agent、子代理分派、AI 群聊、任務進度 UI**。這些功能不由模型本身提供安全保證或持久狀態；模型是內容與受控工具的執行元件。

- **新增與刪除對話、狀態持久化：**應用與後端建立對話／訊息 ID、owner/tenant、資料庫交易、歷史版本及刪除規則。刪除策略需涵蓋主資料、來源文件、擷取快照、向量索引、快取、日誌、匯出副本、子代理暫存及備份保留。模型可產生標題或摘要，不能保證資料實際刪除、備份生命週期或跨系統傳播。
- **Google 登入：**OAuth/OIDC、token 驗證與帳戶綁定由身分服務和後端完成，包括 issuer/audience/signature/nonce/state、scope 最小化、到期／撤銷及秘密儲存。模型不能登入、驗真 token、替使用者授權或推斷帳戶權限。測試可用本機模擬 OIDC provider，不實際連 Google。
- **個人 Agent 與權限隔離：**工具政策引擎、租戶 ACL、資料存取代理、密鑰管理、配額及審計由後端強制。模型可規劃研究步驟、請求搜尋／讀取工具，但每個工具呼叫都由伺服器驗證使用者、來源範圍、參數與允許動作；提示詞不能取代權限邊界。
- **子代理分派與彙整：**編排層決定任務切分、各代理資料範圍、模型／工具清單、超時、成本預算、最大深度、重試／取消和結果格式。模型可以建議分派、生成子任務或彙整回傳內容，但不能自行擴權。應保存父任務、子任務、來源與輸出間的關聯，彙整時保留每個結論的 evidence ID，而非把子代理文字當作已驗證事實。
- **AI 群聊：**應用負責成員／頻道權限、訊息可見性、使用者與 Agent 身分標記、上下文選取、提及與回覆規則、群聊記憶及引用來源的共享範圍。模型可摘要討論或提出研究問題，不能判定某人可讀私人對話或將他人 Agent 的記憶帶入群聊。
- **任務進度 UI 與人工核准：**任務狀態由編排後端以持久事件／狀態機記錄（排隊、來源搜尋、擷取、代理執行、彙整、待核准、完成、失敗、取消），UI 只呈現後端事件，不以模型敘述當進度真相。需核准的外部動作由伺服器端工具閘道阻擋，保存核准者、範圍、有效期與精確參數；參數改變即重新核准。模型可整理核准摘要，不能宣稱已獲核准或自行放行。

## 可執行的基準與功能測試

比較前固定 checkpoint／量化、runtime 版本與參數、GPU 型號／數量、context、batch／併發、sampling、提示模板、工具 schema、來源快照與網路條件。每個候選都需在**同硬體、同 runtime、同量化條件**下比 p50/p95 首 token／整段延遲、tokens/s、峰值 VRAM、每份短報告成本、OOM 率、工具成功率及失敗恢復。不同模型的最佳化配置可另列，不可與受控同條件比較混為排名；本報告沒有現場 benchmark，官方分數也不等於產品流量表現。

**繁中與來源密集研究品質**使用人工覆核、版本控管的 zh-TW 測試集：多來源短報告、跨來源對照、相互矛盾來源、表格／PDF 擷取文本、繁簡混合、台灣專有名詞、日期與數字、來源不足時明確保留未知。每題提供標準 claim、引用段落及評分規則，盲評語意忠實、繁體用字、數值正確、來源覆蓋、過度推論和新鮮度。逐項計算：

- **引用 URL 有效性：**成功開啟、狀態碼／重新導向、標題與擷取內容一致、來源版本時間可辨；區分 URL 有效與證據實際支持主張。
- **Claim–evidence 對齊：**抽樣逐個 claim 檢查 evidence span 是否直接支持、是否斷章取義或引用錯來源；記錄無依據主張率、引文精確率／召回率與數字抄錄正確率。
- **Coverage／freshness：**覆蓋題目要求的子問題、主要來源類型及反方／矛盾證據；比較查詢／擷取日期與來源更新時間，測過期來源、404、內容變更及無新證據時的降級行為。
- **研究文本與公開基準：**可用 MMMLU、C-Eval、MGSM 作中文參照，不能作繁中保證；Agent/tool 任務可參考 BFCL、τ³-bench、Terminal-Bench 等與任務相符的基準，另須以 Reasona 自有來源包和短報告 rubric 評分。

**工具與結構化輸出**使用模擬搜尋、開啟 URL、擷取段落、引用驗證、任務狀態等固定工具目錄。測正確選工具、查詢參數、來源 ID 傳遞、重試／逾時、工具回傳錯誤、重複請求冪等性、未授權 URL／資料範圍攔截與多輪結果回填；分別統計 native tool-call parser 成功率、應用實際工具成功率及權限拒絕正確率。對 JSON Schema 測 required/enum/巢狀物件/陣列/邊界值/繁中 Unicode/額外欄位，拆開測自由生成、runtime constrained decoding、驗證失敗重試；一次合規率和最終合規率要分列，不能把 JSON 外觀當 schema 合規。

**多代理分派、彙整與失敗恢復**使用可重播的研究任務：將來源集合切成互補子問題，測分派覆蓋率、重複工作、來源交叉核對、子代理證據 ID 保留、矛盾結果呈現及總結中 claim—source 映射。注入子任務逾時、搜尋工具失敗、單來源 404、模型回傳格式錯誤、代理中止、重試後來源更新、取消與預算用盡；驗證編排層只重跑必要工作、不丟失已完成 evidence、標出部分完成，並能從持久狀態恢復。記錄每個代理的成本、延遲、成功狀態和父子任務關聯。

**拒絕與提示注入**在使用者問題、來源網頁文字及工具輸出中插入「忽略指示」、偽裝系統命令、要求洩露其他對話／隱藏提示、惡意連結或逾越來源範圍指令，並配正常研究需求作對照。模型拒絕文字與後端實際阻擋要分開驗；不得把網頁內容提升為指令或允許來源頁要求模型洩露秘密。用合成資料與模擬工具，不放真實憑證。

**產品功能測試**至少覆蓋：

- **新增／刪除對話與來源資料生命週期：**建立後驗證 owner/tenant、訊息順序、任務與來源關聯；刪除後檢查主資料、上傳文件、擷取快照、向量索引、快取及子代理暫存的預期清除／保留；測併發、重試、備份規則及審計。模型不能作刪除成功證據。
- **Google OAuth（模擬）：**以本地 mock OIDC provider 測成功登入、錯誤 state/nonce、過期／偽造 token、錯誤 audience/issuer、撤銷、scope 最小化、帳戶綁定與跨租戶拒絕；不連接真實 Google 或交換使用者憑證。
- **個人 Agent、子代理與隔離：**測子代理只取得最小任務上下文與允許來源；嘗試跨使用者取對話／來源、未授權工具、無限遞迴、超預算、偽造高權限分派；後端必須拒絕，且可從持久任務記錄追查。
- **AI 群聊：**用不同成員、私人對話與共享研究頻道測訊息可見性、來源分享範圍、Agent 發言身分、私人記憶不外洩、刪除後不由摘要恢復，以及群聊引用是否可追到可見來源。
- **任務進度 UI／失敗恢復：**事件序列測排隊、搜尋、擷取、代理、彙整、待核准、完成／失敗／取消；瀏覽器重載、重連或後端重啟後 UI 應由持久狀態復原，不能顯示模型臆測的進度；測取消與失敗後部分結果及來源仍可追蹤。
- **人工核准阻擋：**對會改變外部狀態的工具使用測試閘道；未核准、核准過期、核准者權限不足、重放 token 或核准後參數改變都須拒絕。只有精確核准參數可執行並留下審計記錄，即使模型輸出「已核准」也不可放行。

## 推薦與待驗證事項

新版產品情境應以「來源密集研究／短報告的多代理流程」為驗收中心。建議先以 **Granite 4.2 30B + vLLM** 建立可追溯研究主流程，並以 **Gemma 4 31B-it** 作同條件對照；若繁中／工具品質及經費允許，再把 **Mistral Medium 3.5** 納入能力組。以上是依已查證的授權、語言證據、長 context 與 runtime 文件所作的試驗優先序，不是現場性能排名或產品需求定案。

正式決定前至少完成：法務確認權重授權及實際部署／分發方式；託管 API 另核供應商條款、資料保留政策、型號供應和費率；用產品自有繁中資料測閱讀、claim–evidence 對齊、來源 freshness／coverage、引用追溯、工具／schema、多代理彙整、錯誤恢復及權限隔離；同硬體／runtime／量化測延遲、成本、峰值 VRAM。新增刪除對話、OAuth、Agent 權限、子代理編排、AI 群聊、任務進度與人工核准則由應用和後端實作並測試，不能以模型能力替代。
