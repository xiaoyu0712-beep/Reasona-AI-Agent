# AI Agent 平台：來源型研究短報告工作流程與驗收條件

## 文件定位

本文描述「以多代理協作產出附可追溯來源的研究短報告」這項**待驗證產品假設**，並提出供產品與工程討論的工作流程及驗收基線。下列流程與門檻是建議的可測行為，不代表需求已由使用者研究或實際使用證實；應以原型測試、任務觀察及回饋驗證後再定案。

## 暫定假設

- 使用者希望從一段研究問題開始，交由個人 Agent 規劃、分派子代理蒐集材料，再彙整為簡短、附來源且能核查的報告。
- 多代理協作可能有助於並行探索不同子題，但可能增加等待、重複或互相矛盾的內容；應呈現分工與進度，並由主 Agent 負責整合，而非要求使用者自行拼接。
- 暫定短報告包含：標題、重點結論、精簡分析、來源連結及必要的不確定性說明。報告長度、來源數、來源品質門檻及是否必須使用多個代理，均待驗證。
- 視覺方向為黑白灰高級簡約、大圓角與液態玻璃質感。此為介面方向，不應妨礙閱讀、可辨識狀態或鍵盤操作。
- 新增／刪除對話、個人 Agent、子代理分派、Agent 群聊、頂端任務進度及自動任務命名，作為本流程可能需要的產品能力；其必要性與互動細節仍待驗證。

## 建議工作流程

1. **開始研究**：使用者新增對話並輸入研究問題，可補充範圍、受眾、時間界線或偏好。主 Agent 將問題整理成可執行的研究任務；資訊不足時，先提出影響結論的澄清問題，否則採取明示且可調整的預設值。
2. **命名與規劃**：系統依任務內容產生簡短對話名稱，主 Agent 顯示研究子題、預計分工及預期輸出。使用者可在執行前修正規劃或名稱。
3. **分派與並行蒐集**：主 Agent 將彼此可分開處理的子題派給子代理，並保留任務與代理的對應關係。主 Agent 負責避免不必要的重複、追蹤各子題狀態，並在子代理回報後檢查材料是否可用。
4. **追蹤與介入**：頂端進度區以可理解的階段呈現任務狀態。使用者可查看代理分工與回報；Agent 群聊用於同一研究任務內的補充討論，不取代主 Agent 的整合責任。遇到失敗、阻塞或重要歧異時，清楚呈現原因並提供可行的繼續、重試或調整方式。
5. **綜合與核查**：主 Agent 比較各代理的發現，處理重複及衝突，將可支持的結論連結到具體來源。無法判定的衝突、資料缺口或推論限制應保留說明，不得以肯定語氣掩蓋。
6. **交付與後續**：呈現短報告及可開啟的來源，並允許使用者追問或要求修訂。使用者可新增對話開始另一個任務；刪除對話時先確認並清楚說明刪除範圍。個人 Agent 設定可供後續任務沿用，但不應默默改變既有對話中的任務紀錄。

## 建議驗收條件

以下為可供測試的明確行為基線；數量門檻與互動細節屬暫定值，應透過產品驗證調整。

### 任務建立與進度

- 從新增對話輸入研究問題後，系統建立一個可辨識的研究任務，並顯示目前階段、進行中／已完成／受阻狀態；狀態更新不需重新整理頁面。
- 自動任務名稱與輸入內容相關、簡短且不包含無關的通用佔位名稱；名稱可由使用者編輯，編輯後不會被後續狀態更新覆寫。
- 使用者可建立多個彼此獨立的對話；切換對話後，訊息、分工與進度不混入其他對話。
- 刪除對話前有明確確認；確認後該對話從列表及一般檢視中移除，取消則保留原狀。刪除範圍（例如是否連帶移除其任務紀錄）需在產品介面明示並依產品資料政策實作。

### Agent 分工與協作

- 主 Agent 能將任務拆為可辨識的子題，並顯示各子題負責代理與狀態；每份子代理回報可追溯至其所屬子題。
- 子代理未完成、失敗或回報不足時，不得將整體任務標示為無條件完成；需顯示受阻原因或未完成部分。
- Agent 群聊訊息及代理回報保留說話者與時間／順序脈絡，並可辨識其所屬任務；不同對話的討論不得串接。
- 個人 Agent 可被選用於新任務；其名稱與可辨識設定在儲存後可再次查看。任務執行中若設定被修改，當前任務使用的設定版本或生效狀態須清楚可知。

### 來源與報告品質

- 每項可核查的事實性主張均附至少一個可開啟的來源連結，且連結與該主張相鄰或能以清楚標記對應；報告不得以未連結的來源清單取代逐項對應。
- 來源連結須指向所引用的具體頁面或文件，而非僅指向搜尋結果頁；無法取得或核實的來源須標示，不能呈現為已核實證據。
- 報告清楚區分來源直接支持的事實、跨來源綜合出的判斷，以及仍不確定的內容；結論強度不得超出所列證據支持程度。
- 若來源間存在重要矛盾，報告須指出歧異及其對結論的影響；若缺少足夠來源支持某項結論，須降低語氣或明確標示缺口，不得捏造來源、作者、日期或引述。
- 交付內容符合暫定的短報告結構（標題、重點結論、精簡分析、來源及必要限制），各段落內容相關且無明顯重複。具體篇幅與來源數門檻待驗證，不作為本版硬性通過條件。

### 介面與可用性

- 黑白灰、大圓角與液態玻璃樣式下，正文、來源連結、進度狀態及互動元件仍清晰可辨；文字與背景對比符合團隊採用的無障礙標準。
- 進度不得只以顏色表示；重要狀態同時提供文字或其他可辨識線索。互動元件有清楚的焦點、可操作狀態及足夠明確的標籤。
- 使用者能在不離開當前任務的情況下找到代理分工、進度與最終報告；報告中的來源連結可直接開啟。

## 驗證時需回答的問題

- 使用者是否真的偏好由多個代理並行研究，而非單一 Agent 直接完成？分工及進度資訊是否提升信任，還是造成干擾？
- 使用者所說的「短報告」期待多長、包含哪些部分？來源需要多少、何種品質及呈現粒度才足夠？
- 哪些任務值得自動分派；遇到低信心或來源互相矛盾時，使用者希望 Agent 如何提問或呈現限制？
- 新增／刪除對話、個人 Agent 與 Agent 群聊是否為完成此流程的必要能力，及其優先互動方式為何？
- 視覺方向在不同裝置、長篇內容及來源密集畫面中是否仍易讀、易操作？
